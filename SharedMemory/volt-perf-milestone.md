Ongoing work (started 2026-07-03): make Volt's Tier-0 register VM competitive on benchmarks — target ~1.5× PUC-Lua 5.4, beat Ruby(no-YJIT)/PHP/Perl. Full plan: `/home/Yutsuna/.claude/plans/tender-doodling-cupcake.md`.

Benchmarks: `Benchmarks/Recursive/Fibonacci.vl` (fib(35), call-heavy) and `Benchmarks/Primes/IsPrime.vl` (primes≤100k, loop/arith-heavy). Harness `Benchmarks/bench.sh` + `Benchmarks/RESULTS.md`. See [[build-env-krystal-crystal]].

**Phases:** 0 harness ✅, 1 shared register stack ✅, 2 flat dispatch ✅ (marginal — see below), 3 peephole superinstructions ✅ (biggest win yet — see below), 4 Value struct {tag,payload} ✅ (primes ×1.7 more — see below), 5 native-call cleanups ✅ (hygiene, no benchmark movement expected — see below), 6 explicit frame stack ✅ (structural, flat on these benchmarks — see below). **All 6 phases done; target met.**

**Honest baseline (same current toolchain, `krystal -R`, `time` fallback — no hyperfine in this shell):** original VM fib **16.5s** / primes **1.09s** → Phase 1+2 fib **11.7s** (×1.41) / primes **1.04s** (×1.05) → Phase 3 fib **~1.15s** (×10.2 vs P1+2), primes **~0.14s** (×7.4 vs P1+2) → Phase 4 fib **~1.0-1.4s** (flat, noise-bound), primes **~0.08s** (×1.7 vs P3) → Phase 5 fib ~0.83-1.19s, primes ~0.06-0.07s (both flat vs P4) → **Phase 6 fib ~1.0-1.3s (steady ~1.0s), primes ~0.07s (both flat vs P5 — structural change, not a speedup on these benchmarks)**. The earlier "9.8s Phase 1" was crystal-1.19.1 (manually exported) — not comparable; user upgraded krystal to bundle crystal + mold mid-session.

**Phase 3 done (biggest single win of the project):** implemented `Compiler/Peephole.cr` (was a no-op stub), three instruction-count-preserving passes (dead slots → new `NOP` opcode, so `JMP`/`DropMap` pc ranges never need remapping) plus one emitter-level change. New opcodes in `IR/Opcode.cr`: `EQ_INT`/`NE_INT` (typed), `NOP`, `ADD_INT_IMM`/`SUB_INT_IMM`/`EQ_INT_IMM`/`NE_INT_IMM` (8-bit unsigned immediate in the C field), `BR_LT/LE/GT/GE/EQ/NE_INT` + `_IMM` variants (fused compare+branch). (1) `FunctionEmiter#compile_binary` emits typed `EQ_INT`/`NE_INT` when both operands are proven `Int` (kills generic `Value#==` union dispatch for `n % i == 0`). (2) Immediate fusion: `[LOAD_CONST t,k][ADD/SUB/EQ/NE_INT a,b,t]` (k in 0..255) → `[NOP][*_IMM a,b,k]`. (3) Compare+branch fusion — the big one: `[CMP_INT d,b,c][JMP_IF_FALSE d,target]` → `[BR_xx _,b,c][JMP_IF_FALSE unchanged]`; the JMP_IF_FALSE slot is left byte-for-byte untouched and reused purely as a target holder (VM's `BR_xx` handler reads its `.bx` directly via `code[ip].bx`, never dispatches it) — **no boolean `Value` is ever materialised** for an `if`/`while` condition. Safety: requires the compare's dest register to have exactly one reader (the JMP_IF_FALSE) AND that nothing else jumps directly into the JMP_IF_FALSE slot (checked via a chunk-wide jump-target set gathered before fusion — landing there directly would dispatch a real `JMP_IF_FALSE` against a now-stale/unwritten register). (4) MOVE elimination: `[op a=t,...][MOVE home,t]` with `t` dead elsewhere → `[op a=home,...][NOP]` — collapses `i += 1` (`LOAD_CONST`,`ADD_INT`,`MOVE`) to one real instruction. All liveness checks are a simple chunk-wide register read-count scan (`Hash(Int32,Int32)`), sound because `FunctionEmiter`'s register allocator is monotonic single-assignment (`@next_reg` only increments, never reused) — "is this temp dead" reduces to "read-count == 1". `ConstFold.cr` still a no-op stub (neither benchmark has foldable literal-op-literal expressions). Verified: 237/237 specs pass, REPL smoke-test OK (multi-def `extend`/shared-stack reentrancy), both benchmarks correct output.

**Phase 4 done:** rewrote `IR/Value.cr` — Crystal mixed union `Raw = Int64 | Float64 | Bool | String | ::Regex | Nil | HeapObject` replaced by an explicit `struct Value { tag : Tag (UInt8 enum), payload : UInt64 }`. `as_i`/`as_f`/`as_s`/etc. are now `@payload.unsafe_as(T)` bit-reinterprets instead of Crystal's runtime union `.as(T)` type-checks. For `String`/`::Regex`/`HeapObject`, `payload` stores the reference's raw pointer bits completely undisguised (no tag OR'd in) — this is *safe* under Boehm's conservative GC specifically because it's undisguised: the plan explicitly rejected NaN-boxing because OR-ing tag bits into a pointer corrupts the address a conservative scanner needs to recognize, but conservative scanning doesn't care about a field's static type (`UInt64` vs a real pointer type) — it just scans raw memory words for bit patterns that look like valid heap pointers. Safe here because every `Value` lives only inside `Vm@stack` (`Pointer(IR::Value).malloc`, GC-backed since Phase 1). Diff confined to `IR/Value.cr` plus 3 external call sites that pattern-matched on the old `.raw` field directly: `VM/Dispatch/Cmp.cr` (`EQ_CASE`'s regex/string check), `VM/Dispatch/Native.cr` (`to_c_arg`'s FFI arg dispatch), `Compiler/Peephole.cr` (`small_int_const`). Struct stays 16 bytes. Result: primes ×1.7 (bigger than the plan's own ×1.1-1.3 estimate — primes is comparison/arithmetic-bound so `as_i`/`truthy?` traffic dominates), fib flat/no regression (call-bound, not value-unboxing-bound, as expected). 237/237 specs pass.

**Phase 5 done:** native-call path cleanups, confined to `VM/Dispatch/Native.cr`, `VM/Dispatch/Call.cr`, `VM/Frame.cr`, `VM/Vm.cr` (`initialize`/`extend`). (1) `collect_args` (used only by `CALL_NATIVE` — `CALL`/`CALL_METHOD` use the windowed calling convention directly since Phase 1) no longer allocates an `Array`: `Frame` gained `slice(offset, count) : Slice(IR::Value)`, a zero-copy window into `Vm@stack`. (2) `dlopen`/`dlsym` used to be redone on *every* `CALL_NATIVE` (`Dispatch/Native.cr:41-64` in the pre-Phase-5 code); now `Vm#@native_ptrs : Array(Void*)` caches one resolved symbol pointer per `@unit.natives` index, filled lazily on first call via `resolve_native`, grown in `extend` in lockstep with `@unit.natives` (same pattern as `@globals`'s growth there) so REPL `:load` sessions adding new externals get correct fresh cache slots. `call_native`'s `c_args` marshalling switched `Array#map` → `StaticArray(Void*, 4)` to drop that allocation too. Neither benchmark stresses `CALL_NATIVE` (`puts` called once each, not in a loop) so — as expected — no measurable timing change vs Phase 4; this phase is "hygiene," not a benchmark-moving lever. Verified: 237/237 specs pass, output correctness on both benchmarks, plus manual smoke tests — 5 successive `CALL_NATIVE`s through the cached path, and a REPL session `:load`-ing a second external (`abs`) after the first (`puts`) confirming `@native_ptrs` grows and resolves per-index correctly. Found (pre-existing, left alone, out of scope): `to_c_arg`'s `val.as_i.to_u64` raises on negative `Int64` native args — bug predates Phase 3, untouched by Phases 4-5.

**Phase 6 done (all phases complete):** fused the once-per-Volt-call native `execute` recursion into a single dispatch loop over an explicit `frames` stack (`private record CallFrame{chunk, base, ip}`), PUC-Lua style. `CALL`/`CALL_METHOD` now push the caller's resume state + rebind the loop's hot locals to the callee via two `private macro`s (`enter_callee`/`restore_caller` — macros, not methods, so they can reassign the loop's locals in place); `RET` pops. Confined to `VM/Vm.cr` (execute rewrite + record + 2 macros). `execute` stays re-entrant (specs/REPL/`destroy_object`→`call_chunk`): each invocation owns its own `frames` (pre-sized `Array(CallFrame).new(256)`), so a nested call never corrupts an outer loop's stack. Exception-unwind RAII moved from the per-frame `ensure` chain to an explicit deepest-first walk of `frames` inside a single `rescue ex ... raise ex` (safe because `unwind_frame` is a shallow destroy that never re-enters the VM); `@stack_top` restore stays in `ensure`. Early-return drop (`unwind_frame ... if ip<size && !drop_map.empty?`) preserved exactly, now run in the RET handler before pop. **Result: flat within noise on both benchmarks** — the native call + `ensure` landing pad removed per Volt call is ~offset by `frames` push/pop bookkeeping; fib's residual cost is Value boxing / `eval_arith` dispatch, not Crystal call overhead. A Phase-2-style "structural change that doesn't move these benchmarks" finding. Two concrete wins regardless: (1) unbounded Volt recursion now bounded by `STACK_CAPACITY` → clean `VoltRuntimeError` "stack overflow" instead of native Crystal-stack segfault (verified w/ non-terminating recursion); (2) unlocks tail-call elim (not implemented; fib isn't tail-recursive). 237/237 specs pass incl. RAII + exception-path specs. **Also fixed the pre-existing `to_c_arg` bug** (flagged in Phase 5): `val.as_i.to_u64` → `to_u64!` (unchecked/wrapping) so negative `Int64` native args pass as raw two's-complement bits instead of raising `OverflowError`. One-liner in `VM/Dispatch/Native.cr`. **No known correctness issues remain.**

**Competitor snapshot (same machine, `time`, no hyperfine):** Volt fib ~0.83-1.19s vs Lua 0.86s / Ruby 0.97s / PHP 0.47s / Python 1.13s. Volt primes ~0.06-0.07s vs Lua 0.10s / Ruby 0.19s / PHP 0.07s (Python's 0.02s is bogus — `Benchmarks/Primes/IsPrime.py` never calls `count_primes`, needs fixing before it's a real comparison). Volt fib is now roughly on par with Lua (the two overlap run-to-run, noise-bound); Volt primes *beats* Lua and Ruby outright and is within ~1x of PHP. architecture.md's ~1.5x-Lua target is met with room to spare on both benchmarks now.

**Phase 2 finding (important):** flat dispatch did NOT help this *recursive* VM. Inlining all opcode bodies into `execute` REGRESSED fib (→12.5s) because `execute` recurses once per Volt CALL, so a bigger frame/prologue is paid 30M times. Removing begin/ensure changed nothing. Kept only safe parts: enum-constant `when` jump tables (not `.pred?` linear chains — that was the first regression, ~14s), raw pointer `regs` (no bounds checks), hoisted code/size/consts; arith/cmp bodies stay DELEGATED to eval_arith/eval_cmp (also converted to enum-const jump tables) to keep `execute` small. Real next levers: fib→Phase 6 (non-recursive loop), primes→Phase 3/4 (boxing/superinstructions, dispatch was never primes' bottleneck).

**Phase 1 done:** `VM/Frame.cr` is now a thin struct wrapping `Pointer(IR::Value)` (a window into `Vm@stack`, a single `Pointer(IR::Value).malloc(1<<20)`). `Vm#execute(chunk, base)` replaces the old per-call `Frame`+Array; Lua-style copy-free windows (callee base = caller base + A + 1, results land at base-1). `call_chunk`/`call_chunk_at` kept as cold Array-boxing wrappers for specs/REPL. Stale-slot RAII fix: `Chunk#raii_regs` (union of drop_map + scope_tables regs) nil-init'd per frame; empty for fib/primes. Result: **fib 17.2s → 9.8s (×1.75)**, 237 specs pass, all RAII/OO samples correct, REPL works.

**Primes now parses** (user added postfix-`if` in ParseControlFlow/ParseExpression/Prec, giving `.if?`/`.unless?` a new `Prec::Modifier` led-precedence). That introduced a regression, now FIXED: `ParseExpression.cr#parse_expr`'s cross-newline continuation check (`break if continuation <= min_prec`) let a newline get skipped whenever the next line's leading token had precedence > min_prec — true for `Modifier` at statement level (min_prec=None=0 < Modifier=1). So `@x = 5` followed by a block `if` on the next line got glued into `@x = (5 if ...)`, leaving the `if`-block's own `end` unconsumed → cascading stray `end`. Fix (237/237 specs pass): `break if continuation <= min_prec || continuation.modifier?` — postfix modifiers never span a newline, regardless of context, while genuine binary-operator line continuations still work.
